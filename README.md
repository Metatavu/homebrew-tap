# Metatavu packages

Public distribution for Metatavu's command-line tools. Binaries only — the source lives in
each tool's own repository.

## macOS

```sh
brew tap Metatavu/tap
brew install metatavu/tap/severa
```

## Linux

```sh
curl -sfL https://raw.githubusercontent.com/Metatavu/homebrew-tap/main/install.sh | sh -s -- severa
```

Installs to `$HOME/.local/bin` by default; pass `--prefix` for somewhere else, and
`--version` to pin. Re-run it to upgrade.

Homebrew works on Linux too, but few people run it there, so the script is the expected
route. It verifies the download against the published checksum, so there is one thing to
trust — this script — rather than two.

## Containers

```sh
docker pull ghcr.io/metatavu/severa-cli:latest
```

Preferred for CI: an image that already contains the tool beats installing one per job.

## Tools

| Tool | Source | Platforms |
|---|---|---|
| `severa` | [severa-cli](https://github.com/Metatavu/severa-cli) | macOS arm64, Linux amd64, Linux arm64 |

No Intel macOS build: Apple stopped shipping those Macs in 2023, and Rosetta translates x86
to arm rather than the reverse, so there is nothing to fall back to. Windows is covered by
WSL through the Linux amd64 build.

The Linux amd64 binary is statically linked and runs on any distribution. The arm64 one needs
glibc 2.39 or newer, because GraalVM's musl toolchain is x86_64 only; the install script
checks for this and says so rather than letting the binary fail with an unexplained
`GLIBC_2.39 not found`.

## Releases

Tags are tool-prefixed, `severa-v0.1.0`, since this repository holds releases for every tool.

Formulae here are generated by each tool's release workflow rather than edited by hand, so a
release and its formula cannot drift apart. That workflow needs a token with write access to
this repository.
